02. Understanding Core Components (View, Text, TextInput)

Welcome back to the world of React Native (RN)! Previously, we looked at how RN converts JavaScript code into native mobile apps. Today, we're going to dive deep into the fundamental building blocks that make up your app's screens: Core Components.

1. Why You Can't Use Standard HTML Tags

If you're accustomed to web development, you're likely used to grouping things with <div>, writing text inside <span> or <p>, and taking user input via <input>. However, in React Native, you cannot use these standard HTML tags.

Why is that? As we learned in the previous module, RN doesn't spin up a web browser. Instead, it maps directly to pure native UI on mobile devices. This means that instead of HTML, which browsers understand, we must use specific "dedicated components" that iOS and Android can interpret.

💡 Core Metaphor: "Standardized Lego Blocks"
If web development is like freely painting on a blank canvas, mobile app development with RN is like building with Lego blocks of specific sizes. Instead of web tags, RN provides dedicated Lego blocks (Core Components) that are perfectly tailored for mobile.

2. RN Core Component Mapping Guide

Let's take a look at a table showing how the web tags you know translate into RN components.

Web (HTML) React Native Role Native Mapping (iOS / Android)
<div> <View> Container for UI, layout structure UIView / ViewGroup
<p>, <span> <Text> Displays text on screen UITextView / TextView
<input> <TextInput> Receives text input from the user UITextField / EditText
<img> <Image> Displays an image UIImageView / ImageView
<button> <Button>, <TouchableOpacity> Handles click/touch events UIButton / Button

A Closer Look at Core Components

  1. <View>: The most fundamental block. It acts as a container to hold other components and is essential for building layouts using CSS flexbox.
  2. <Text>: In RN, every single string of text must be wrapped inside a <Text> component. Writing text directly inside a <View> will throw an error!
  3. <TextInput>: Used when you need to capture user input, such as a password or a search query.

3. Practice: Publishing a Profile Card UI

Based on what we've learned, let's build a simple Profile Card UI.

import React from 'react';
import { View, Text, TextInput, Image, StyleSheet, TouchableOpacity } from 'react-native';

export default function ProfileCard() {
  return (
    <View style={styles.container}>
      {/* Profile Image (Using a placeholder URL) */}
      <Image 
        source={{ uri: 'https://via.placeholder.com/100' }} 
        style={styles.profileImage} 
      />
      
      {/* User Name and Status (Using Text component) */}
      <Text style={styles.name}>Developer John Doe</Text>
      <Text style={styles.bio}>Mastering React Native! 🚀</Text>

      {/* Status Update Area (Using TextInput) */}
      <TextInput 
        style={styles.input} 
        placeholder="Update your status message." 
      />

      {/* Button Area (Using TouchableOpacity) */}
      <TouchableOpacity style={styles.button}>
        <Text style={styles.buttonText}>Save</Text>
      </TouchableOpacity>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    padding: 20,
    backgroundColor: '#f5f5f5',
    borderRadius: 10,
    alignItems: 'center',
    margin: 20,
  },
  profileImage: {
    width: 100,
    height: 100,
    borderRadius: 50,
    marginBottom: 15,
  },
  name: {
    fontSize: 20,
    fontWeight: 'bold',
    marginBottom: 5,
  },
  bio: {
    fontSize: 14,
    color: '#666',
    marginBottom: 15,
  },
  input: {
    width: '100%',
    height: 40,
    borderColor: '#ddd',
    borderWidth: 1,
    borderRadius: 5,
    paddingHorizontal: 10,
    backgroundColor: '#fff',
    marginBottom: 15,
  },
  button: {
    backgroundColor: '#007AFF',
    paddingVertical: 10,
    paddingHorizontal: 20,
    borderRadius: 5,
  },
  buttonText: {
    color: '#fff',
    fontWeight: 'bold',
  }
});

If you run the code above, you'll see a polished profile card appear on the screen, structured with a <View>, displaying a picture via <Image>, rendering words with <Text>, and accepting input through <TextInput>.

Chapter Summary

  • No HTML Tags: Because RN builds native apps, you cannot use web markup languages like HTML (e.g., <div>, <span>).
  • Component Mapping: Replace <div> with <View>, text containers with <Text>, and input fields with <TextInput>.
  • Mobile-Optimized Assembly: By utilizing these provided "standardized Lego blocks," you can safely construct a native UI optimized for the mobile environment.
