07. OpenID Connect (OIDC)

Teams often say they “log users in with OAuth.” Strictly speaking, OAuth 2.0 is not an authentication protocol. OpenID Connect adds the missing identity layer on top of OAuth.

Why OAuth Alone Is Incomplete for Login

OAuth answers: “May this client call that API on the user’s behalf?” Login needs: “Who is sitting at the browser, and what is their email/name/verification status?” Access tokens alone do not standardize those answers across IdPs.

OIDC as an Authentication Layer

OIDC extends OAuth with ID Tokens, a UserInfo endpoint, standard scopes (openid, profile, email), and discovery documents.

GET /authorize?
  response_type=code&
  client_id=my-app&
  redirect_uri=https://app.example.com/callback&
  scope=openid profile email&
  state=abc&
  nonce=n0nce-value

Including openid makes the flow OIDC. Token responses often include an ID Token alongside the access token.

async function verifyIdToken(idToken, jwks, clientId, expectedNonce) {
  const { payload } = await jose.jwtVerify(idToken, jwks, {
    issuer: "https://auth.example.com/",
    audience: clientId
  });
  if (payload.nonce !== expectedNonce) throw new Error("INVALID_NONCE");
  return payload;
}

Anti-pattern: sending ID Tokens to APIs as Bearer credentials. APIs should authorize with access tokens.

UserInfo

GET /userinfo
Authorization: Bearer <access_token>

Use UserInfo when profile claims are not fully embedded in the ID Token.

Chapter Summary

  • OAuth authorizes APIs; OIDC standardizes authentication.
  • ID Tokens prove login to clients; access tokens authorize APIs.
  • Validate audience and nonce for ID Tokens.
  • OIDC unlocks portable profile claims and multi-app SSO.
