11. Open-Source IAM: GLUU and Keycloak

When data residency, custom flows, or existing directories directories require self-hosting, open-source IAM platforms let you run your own authorization server / IdP. Keycloak and GLUU are common choices.

Why Build Your Own Authorization Server?

  • Keep identity data on-prem or in a private cloud
  • Implement specialized authentication journeys
  • Reduce vendor lock-in and optimize licensing
  • Continue using LDAP/AD as the authoritative store

Keycloak at a Glance

Keycloak provides OIDC/SAML, realm-based multi-tenancy, identity brokering, LDAP/AD user federation, roles/groups, admin APIs, and MFA options.

docker run -p 8080:8080 \
  -e KEYCLOAK_ADMIN=admin \
  -e KEYCLOAK_ADMIN_PASSWORD=admin \
  quay.io/keycloak/keycloak:latest start-dev

Create a realm, register clients and redirect URIs, map roles, then point applications at the Keycloak issuer.

GLUU at a Glance

GLUU targets enterprise IAM/SSO packaging: authorization server capabilities, directory-centric identity, SAML/OIDC app connectivity, and extensible MFA/custom scripts. Choose based on your organization’s packaging needs, support model, and operational familiarity—always re-check current licensing and patch policies.

Directory Integration and MFA

Design Source of Truth carefully, map attributes (mail → email), translate AD groups into application roles, and sync disablement so leavers lose SSO immediately.

function requireMfa(req, res, next) {
  if (req.user?.acr !== "mfa") {
    return res.status(403).json({ error: "mfa_required" });
  }
  next();
}

Enforcing MFA at the IdP upgrades every connected app at once.

Chapter Summary

  • GLUU and Keycloak enable self-hosted IdP/authorization servers.
  • LDAP/AD federation preserves enterprise directories while offering OIDC/SAML.
  • Central MFA strengthens every relying party simultaneously.
  • Source of truth, mapping, HA, and patching decide production success.
