05. Authorization Code Grant

The Authorization Code Grant is the workhorse OAuth 2.0 flow—and the modern default. It standardizes the journey from login button to API call while keeping valuable tokens off the browser redirect channel.

End-to-End Sequence

  1. User clicks “Login with IdP”
  2. Client redirects to the authorization server’s /authorize
  3. User authenticates and consents
  4. IdP redirects back with a short-lived code
  5. Client backend exchanges the code at /token
  6. Client calls APIs with the access token
GET https://auth.example.com/authorize?
  response_type=code&
  client_id=my-web-app&
  redirect_uri=https://app.example.com/oauth/callback&
  scope=orders:read profile&
  state=random-csrf-token

Code Callback and Token Exchange

GET https://app.example.com/oauth/callback?code=SplxlOBeZQQYbYS6WxSbIA&state=random-csrf-token

The code is not an access token. The confidential client exchanges it on the back channel:

POST /token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code&
code=SplxlOBeZQQYbYS6WxSbIA&
redirect_uri=https://app.example.com/oauth/callback&
client_id=my-web-app&
client_secret=SECRET

Why Issue a Temporary Code First?

Browser redirects are a noisy front channel—history, proxies, Referer headers, and extensions can leak URL data. Delivering access tokens directly (the old Implicit flow) widens that exposure. A short-lived, usually one-time code is exchanged over a server-to-server HTTPS POST, so the valuable token never rides the redirect.

Front-channel (browser): short-lived code
Back-channel (server POST /token): access / refresh tokens

Implementation Checklist

  • Generate and validate state (CSRF defense)
  • Exact-match registered redirect_uri
  • Reject reused authorization codes
  • Never log raw tokens
  • Public clients must use PKCE

Chapter Summary

  • Authorization Code Grant is the recommended OAuth 2.0 flow.
  • Browsers receive temporary codes; backends exchange them for tokens.
  • The design keeps access tokens off the exposed front channel.
  • Validate state, redirect URI, and one-time codes every time.
