13. BFF (Backend for Frontend) Design Pattern

SPA browsers are hostile environments for secrets. The modern answer is a Backend for Frontend: keep access and refresh tokens on the server, and give the browser only an HttpOnly session cookie.

What a BFF Does in OAuth

  1. Runs Authorization Code (+ PKCE) exchange
  2. Stores tokens in server-side sessions (often Redis)
  3. Sets an HttpOnly Secure session cookie for the SPA
  4. Attaches Bearer tokens only on server-to-API calls
[Angular SPA] --session cookie--> [BFF]
                                       | Authorization: Bearer
                                       v
                                 [Resource API / ORDS]

Why Keep Tokens Out of the Browser?

  • XSS cannot easily exfiltrate bearer strings from LocalStorage
  • Refresh/rotation logic concentrates in one place
  • IdP details stay behind the BFF while Angular stays simple

Login-to-API Sequence

app.get("/auth/callback", async (req, res) => {
  const tokens = await exchangeCode({
    code: req.query.code,
    codeVerifier: req.session.codeVerifier
  });
  req.session.accessToken = tokens.access_token;
  req.session.refreshToken = tokens.refresh_token;
  res.redirect("https://app.example.com/");
});

app.get("/api/orders", requireSession, async (req, res) => {
  const data = await fetch("https://api.example.com/orders", {
    headers: { Authorization: `Bearer ${req.session.accessToken}` }
  }).then((r) => r.json());
  res.json(data);
});

CSRF Becomes Mandatory Again

Automatic cookie attachment reintroduces CSRF. Combine SameSite cookies, CSRF tokens, and Origin checks on state-changing methods.

this.http.get<Order[]>("/api/orders", { withCredentials: true });

Chapter Summary

  • BFF holds OAuth tokens; browsers hold only session cookies.
  • Removing tokens from JS sharply reduces XSS blast radius.
  • Cookie sessions require deliberate CSRF defenses.
  • Ideal for high-security browser SPAs despite added session ops.
