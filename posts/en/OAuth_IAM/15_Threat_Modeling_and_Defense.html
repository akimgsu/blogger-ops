15. Threat Modeling and Defense

Shipping a correct OAuth flow is not the finish line. Attackers abuse operational gaps—XSS, logs, cookies, and stale trust. This final chapter maps major threats and defenses, including Zero Trust continuous authorization.

Threat-Modeling Questions

  1. Where are tokens created, stored, transmitted, and destroyed?
  2. Who can intercept or replay each artifact?
  3. What is the blast radius after theft?
  4. Can you detect, revoke, rotate keys, and force step-up auth?

Inventory assets first: access/refresh/ID tokens, session cookies, client secrets, and signing keys.

Token Hijacking Scenarios

XSS theft

Move tokens to HttpOnly cookies or BFF sessions, enforce CSP, and shorten access TTLs.

Log and URL leakage

Never put bearer tokens in query strings; mask secrets in logs; force HTTPS.

Refresh-token theft

async function refresh(presentedToken) {
  const saved = await store.get(presentedToken);
  if (!saved) {
    await store.revokeFamily(presentedToken);
    throw new Error("REFRESH_REUSE_DETECTED");
  }
  const next = await issueRotatedTokens(saved);
  await store.invalidate(presentedToken);
  return next;
}

Replay Attacks

Replay resubmits captured codes or tokens. Defend with short expirations, one-time codes, OIDC nonce checks, sender-constrained tokens when needed, and step-up authentication for sensitive actions.

CSRF and SameSite

Cookies auto-attach—great for UX, dangerous for CSRF. Use SameSite=Lax/Strict, OAuth state, CSRF headers, and Origin validation.

if (req.headers.origin !== "https://app.example.com") {
  return res.status(403).json({ error: "origin_denied" });
}

Zero Trust Philosophy

Zero Trust rejects “trusted network location.” Every request is authenticated and authorized continuously with least privilege, device/risk signals, short-lived credentials, and step-up MFA for privileged operations.

[Request] -> Authenticate -> Authorize(policy) -> Risk engine
                              |- allow / deny / step-up

Final Defense Checklist

  1. Auth Code + PKCE only; no Implicit/Password grants
  2. Short access tokens; rotated, well-protected refresh tokens
  3. Minimize browser-held secrets (BFF/HttpOnly)
  4. Strict JWT validation (alg/iss/aud/exp)
  5. CSRF + XSS defenses and CSP
  6. Key management, audit logs, and emergency revoke playbooks

This series began by separating authentication from authorization and ends with attacker-driven defense. Standards plus threat-informed operations are what make identity security real.

Chapter Summary

  • Hijacking and replay demand short TTLs, one-time codes, nonces, and refresh rotation.
  • CSRF rides on cookie auto-attachment—mitigate with SameSite, state, and CSRF tokens.
  • Zero Trust requires continuous verification and least privilege, not one-time login trust.
  • Protocol correctness must combine with XSS/CSRF, key ops, and revoke readiness.
