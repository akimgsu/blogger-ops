03. Token-Based Systems

As APIs and microservices spread, “the server must remember every login” became expensive. Token-based systems emerged so requests can carry verifiable proof of identity and permissions.

What Is a Token?

A token is a string that proves who is calling and what they may do. Clients typically send it as:

Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...

Common forms include opaque tokens (require introspection) and JWTs (self-contained claims). Access, refresh, and ID tokens serve different purposes covered later in the series.

Benefits of Stateless Servers

  • Horizontal scaling: any instance can verify with shared keys—no sticky sessions
  • Service propagation: gateways verify once and forward identity downstream
  • Client diversity: browsers, mobile apps, CLI tools, and jobs share one header pattern

Cryptographic Verification Without Remembering Tokens

If a token’s integrity can be proven mathematically, servers can trust its claims without a session database lookup.

HMAC (shared secret)

Easy to implement, but every verifier needs the secret—painful as services multiply.

Public-key signatures (preferred in distributed systems)

The authorization server signs with a private key; resource servers verify with public keys published via JWKS.

function verifyAccessToken(token, publicKey) {
  return jwt.verify(token, publicKey, {
    algorithms: ["RS256"],
    issuer: "https://auth.example.com/",
    audience: "https://api.example.com"
  });
}

Verification typically checks signature, issuer, audience, expiration, and scopes/roles.

Trade-offs of Stateless Tokens

  • Immediate revocation is harder—use short TTLs, denylists, or introspection
  • Avoid stuffing sensitive PII into JWT payloads
  • Private-key compromise breaks trust system-wide—key management is critical

Chapter Summary

  • Tokens enable request-level proof without central session lookups.
  • Digital signatures let APIs trust claims without storing every token.
  • Asymmetric verification scales well across microservices.
  • Stateless designs trade easy revocation for scalability and require strong key hygiene.
