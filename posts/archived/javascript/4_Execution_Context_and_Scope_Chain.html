Part 4: Execution Context and the Scope Chain

Where variables are visible and how functions run is explained by Execution Context and the Scope Chain.

1. What Is an Execution Context?

An EC is the environment for a running code fragment, pushed onto the Call Stack: Global, Function, and (avoid) Eval contexts.

2. Building Blocks

  • Lexical/Variable Environment — identifier bindings
  • Scope chain — outer references for lookup
  • this binding — call-site dependent (Part 6)

3. Creation vs Execution

function demo(a) {
  console.log(a); // 1
  console.log(b); // undefined (var hoisted)
  // console.log(c); // TDZ for let
  var b = 2;
  let c = 3;
}

4. Hoisting

Identifiers are registered in the creation phase. Function declarations are fully initialized; var becomes undefined; let/const stay in the TDZ.

5. Lexical Scope

Scope is decided by where code is written, not where it is called.

function outer() {
  const x = "outer";
  return function inner() { console.log(x); };
}
outer()(); // "outer"

6. Blocks and Loops

for (let i = 0; i < 3; i++) setTimeout(() => console.log(i), 0); // 0 1 2
for (var j = 0; j < 3; j++) setTimeout(() => console.log(j), 0); // 3 3 3

Chapter Summary

  • Execution contexts stack on the call stack.
  • Lexical environments hold bindings and outer links.
  • Hoisting is creation-phase registration; let/const have a TDZ.
  • JS is lexically scoped—definition site beats call site for free vars.
  • var vs let explains classic loop + async bugs.
