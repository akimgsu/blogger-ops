Part 6: Demystifying this Binding Rules (Including Arrow Functions)

For ordinary functions, this follows the call site. Arrow functions are different—they use lexical this.

1. Four Binding Rules

Default

function show() { console.log(this); }
show(); // globalThis (non-strict) or undefined (strict)

Implicit

user.greet(); // this === user
const greet = user.greet; greet(); // this lost

Explicit

fn.call(obj, a, b);
fn.apply(obj, [a, b]);
const bound = fn.bind(obj);

new

function Person(name) { this.name = name; }
const p = new Person("Grace");

2. Priority

new > explicit (call/apply/bind) > implicit (obj.fn) > default.

3. Arrow Functions

const timer = {
  label: "tick",
  start() {
    setInterval(() => console.log(this.label), 1000); // timer
  },
};

Arrows have no own this, cannot be used with new, and are a poor fit as method bodies. Prefer regular methods; use arrows inside callbacks.

4. Class Field Arrows

class Button {
  onClick() { console.log(this.label); }
  onClickArrow = () => { console.log(this.label); };
}

Convenient for listeners, but each instance gets its own function copy.

Chapter Summary

  • Regular-function this is call-site driven.
  • Priority: new > explicit > implicit > default.
  • Extracting methods as callbacks often loses this.
  • Arrows use lexical this; avoid as constructors/method bodies.
  • Class-field arrows trade convenience for per-instance cost.
