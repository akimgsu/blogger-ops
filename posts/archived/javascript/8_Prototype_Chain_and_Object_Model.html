Part 8: Prototype Chains and JavaScript’s Object Model

Even with class syntax, JavaScript’s real model is prototype-based. Property lookup walks the prototype chain.

1. Delegation via [[Prototype]]

const animal = { eat() { return "yum"; } };
const dog = Object.create(animal);
dog.bark = () => "woof";
dog.eat(); // found on prototype

2. Terminology

  • [[Prototype]] — actual delegation target
  • __proto__ — legacy accessor
  • Fn.prototype — becomes instance [[Prototype]] under new
Object.getPrototypeOf(p) === Person.prototype; // true

3. What new Does

const instance = Object.create(Constructor.prototype);
const result = Constructor.apply(instance, args);
return (result && typeof result === "object") ? result : instance;

4. class as Sugar

class Dog extends Animal {
  speak() { return `${this.name} barks`; }
}
Object.getPrototypeOf(Dog.prototype) === Animal.prototype; // true

5. Shadowing and Pollution Defenses

Reads walk the chain; writes usually create own properties. For dictionaries, prefer Map or Object.create(null).

Chapter Summary

  • Prototype-chain delegation is the core object model.
  • Fn.prototype becomes instance [[Prototype]] under new.
  • class wraps prototype linking in clearer syntax.
  • Writes typically shadow on the instance.
  • Defend against pollution with null-prototype objects or Map.
