Part 11: ES Modules (ESM) vs CommonJS

ESM is the modern standard; CommonJS remains common in Node. Their loading and binding models differ in important ways.

1. Quick Comparison

  • ESM: import/export, static by default, tree-shake friendly, browser-native
  • CJS: require/module.exports, synchronous, dynamic paths easy

2. Syntax

export const PI = 3.14;
export default function sum(list) { return list.reduce((a, b) => a + b, 0); }
import sum, { PI } from "./math.js";

module.exports = { add };
const { add } = require("./math.cjs");

3. Live Bindings vs Snapshots

export let count = 0;
export function inc() { count += 1; }
// ESM importers see live updates to count

4. Dynamic import and Node Interop

const mod = await import(condition ? "./a.js" : "./b.js");
import { createRequire } from "node:module";
const require = createRequire(import.meta.url);

Use "type": "module", .mjs, and .cjs to control formats. Prefer ESM for new code; avoid circular dependencies when possible.

Chapter Summary

  • ESM is the standard static module system; CJS is Node’s classic sync system.
  • ESM offers live bindings and better tree-shaking; use import() for dynamic loads.
  • CJS uses require/module.exports with more value-copy feel.
  • Node interop depends on type/mjs/cjs.
  • Avoid cycles; default new projects to ESM.
