Part 7: JavaScript Functions as First-Class Citizens

In JavaScript, functions are values: assignable, passable, returnable, and storable—and they are objects too.

1. First-Class Basics

const add = (a, b) => a + b;
function compute(fn, a, b) { return fn(a, b); }
function makeAdder(x) { return (y) => x + y; }
greet.version = "1.0"; // functions are objects

2. Higher-Order Functions

nums.filter((n) => n % 2 === 0);
nums.map((n) => n * n);
function withLogging(fn) {
  return function (...args) {
    console.log("args:", args);
    return fn(...args);
  };
}

3. Callbacks and IoC

Callbacks invert control and enable async APIs, but nesting can become callback hell—Promises help (Part 10).

4. Purity vs Side Effects

function tax(price, rate) { return price * rate; } // pure
function addToTotal(n) { total += n; return total; } // impure

Prefer a pure core with an impure I/O shell.

5. Currying, Partial Application, Composition

const curryAdd = (a) => (b) => (c) => a + b + c;
const pipe = (...fns) => (value) => fns.reduce((acc, fn) => fn(acc), value);

Chapter Summary

  • JS functions are first-class values and objects.
  • Higher-order functions power map/filter/decorators.
  • Callbacks enable IoC but can deepen nesting.
  • Currying, partial application, and composition assemble small functions.
  • Separating pure logic from side effects improves testability.
