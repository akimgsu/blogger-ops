Part 14: V8-Friendly Code and Memory Leak Prevention

Keep shapes V8 can optimize, and ensure objects don’t stay reachable longer than they should. Measure first.

1. Stable Shapes and Monomorphic Calls

function Point(x, y) { this.x = x; this.y = y; } // fix shape at construction
function stringLen(s) { return s.length; }       // keep hot functions narrow

2. Arrays Prefer Packed Homogeneous Elements

const xs = [1, 2, 3, 4]; // good
const ys = [1, , 3];     // holey — worse
const zs = [1, 2, "3"];  // mixed — worse

3. Typical Leaks

class Widget {
  constructor(el) {
    this.el = el;
    this.onClick = () => this.render();
    el.addEventListener("click", this.onClick);
  }
  destroy() {
    this.el.removeEventListener("click", this.onClick);
    this.el = null;
  }
  render() {}
}

Also watch closures retaining huge data, unbounded caches, and retained DOM nodes.

4. WeakMap and Dispose

const metadata = new WeakMap();
metadata.set(obj, info); // entry can go away with the key

Prefer explicit dispose for deterministic cleanup.

Chapter Summary

  • V8 likes shape-stable objects and monomorphic calls.
  • Packed, homogeneous arrays optimize better.
  • Measure first; fix algorithmic complexity before micro-tuning.
  • Leaks come from lingering references.
  • Design lifetimes with WeakMap and explicit dispose.
