Part 15: Coercion Pitfalls and Defensive Programming

JavaScript often coerces values to fit an operation. Convenience hides sharp edges around ==, +, and boolean contexts.

1. Implicit vs Explicit

1 + "2";          // "12" — implicit
Number("2");      // 2 — explicit

Don’t rely on implicit coercion at boundaries—convert explicitly.

2. Truthy / Falsy and ==

Falsy: false, 0, "", null, undefined, NaN, 0n. Arrays and objects are truthy.

const port = input ?? 3000; // only null/undefined
0 == false; // true — prefer ===

3. + and Number Quirks

"1" + 2;           // "12"
Number("");        // 0
Number(null);      // 0
parseInt("12px", 10); // 12
Number.isNaN(NaN); // true

4. Defensive Checklist

function createUser(dto) {
  if (dto == null || typeof dto !== "object") throw new TypeError("dto must be object");
  const name = String(dto.name ?? "").trim();
  const age = Number(dto.age);
  if (!Number.isInteger(age) || age < 0) throw new Error("invalid age");
  return { name, age };
}
const city = user?.address?.city ?? "Unknown";

Layer ESLint (eqeqeq), TypeScript, and runtime schemas (Zod/Valibot) for external input.

5. Safe Habits

  1. Compare with ===
  2. Default nullish values with ??
  3. Validate numbers with Number.isFinite/isInteger
  4. Don’t erase valid 0/"" with ||

Chapter Summary

  • JS coerces values to match operator/context needs.
  • Falsy includes 0/""/null/undefined/NaN; []/{} are truthy.
  • Default to ===; many teams allow only == null.
  • Handle + and Number/parseInt explicitly at boundaries.
  • Defense is validation + ??/?. + schemas + lint/types.
