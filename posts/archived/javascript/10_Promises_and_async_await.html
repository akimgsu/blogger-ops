Part 10: Promises and async/await — A Practical Guide

Promises and async/await turn callback pyramids into linear control flow.

1. Promise States

pending → fulfilled or rejected, then immutable.

new Promise((resolve, reject) => {
  ok ? resolve({ id: 1 }) : reject(new Error("fail"));
}).then(console.log).catch(console.error);

2. Chaining and async/await

async function loadUser(id) {
  const res = await fetch(`/api/users/${id}`);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json();
}

Async functions always return Promises. Always handle rejections.

3. Parallel vs Serial

const [a, b] = await Promise.all([fetchA(), fetchB()]);
await Promise.allSettled([job1(), job2()]);

Also useful: race, any, and timeout races.

4. Production Patterns

async function mapPool(items, limit, fn) {
  const results = new Array(items.length);
  let i = 0;
  async function worker() {
    while (i < items.length) {
      const idx = i++;
      results[idx] = await fn(items[idx]);
    }
  }
  await Promise.all(Array.from({ length: Math.min(limit, items.length) }, () => worker()));
  return results;
}

5. Anti-Patterns

  • Serializing independent awaits in a loop
  • Async Promise executors
  • Floating promises without .catch

Chapter Summary

  • Promises are one-way state machines.
  • then-chains and async/await express the same model.
  • Parallelize independent work with all/allSettled.
  • Always handle rejections.
  • Avoid serial-await abuse, async executors, and floating promises.
