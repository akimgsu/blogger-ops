Part 3: Primitives vs References and Immutability

Many bugs come from misunderstanding whether a value was copied or a reference was shared.

1. Definitions

  • Primitive: the value itself is copied.
  • Object/Reference: a reference to heap memory is copied; the same object is shared.
let a = 10; let b = a; b = 20; // a stays 10
let obj1 = { n: 10 }; let obj2 = obj1; obj2.n = 20; // obj1.n is 20

2. Function Arguments

Arguments are pass-by-value, but for objects that value is a reference. Distinguish reassignment from mutation.

function bumpObj(o) { o.count += 1; }
function reassign(o) { o = { count: 999 }; }

3. === Meaning

{} === {}; // false — different objects
const a = {}; const b = a; a === b; // true

4. Immutability

Don’t change the old value—create a new one. Primitives are already immutable; the hard part is object/array mutation.

const nextUser = { ...user, age: 31 };
const nextList = [...list, 4];
// Spread is shallow — copy nested paths explicitly when needed

5. Object.freeze Limits

Object.freeze is shallow. Prefer immutable-update habits (or libraries like Immer) over relying on freeze alone.

6. Copying Options

Shallow: spread / Object.assign. Deep: structuredClone (with limits). JSON round-trip loses many types.

Chapter Summary

  • Primitives copy by value; objects share by reference.
  • Object arguments expose internal mutations to callers.
  • Immutability creates new snapshots instead of in-place changes.
  • Spread is shallow; nest carefully or use structuredClone.
  • Object.freeze is shallow—design patterns matter more.
