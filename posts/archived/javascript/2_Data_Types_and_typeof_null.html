Part 2: JavaScript Data Types and the Secret of typeof null

JavaScript’s type system looks simple until historical quirks—especially typeof null === "object"—collide with dynamic typing.

1. ECMAScript Type Taxonomy

Primitives: Undefined, Null, Boolean, Number, BigInt, String, Symbol.

Objects: plain objects, arrays, dates, maps, and functions (callable objects). Only functions report "function" from typeof.

typeof {};           // "object"
typeof [];           // "object"
typeof function(){}; // "function"
typeof null;         // "object"

2. typeof Cheat Sheet

typeof undefined;   // "undefined"
typeof 123n;        // "bigint"
typeof Symbol();    // "symbol"
typeof class A {};  // "function"
typeof notDeclared; // "undefined" (no ReferenceError)

3. Why typeof null === "object"

This is a legacy implementation bug, not intentional design. Early engines tagged objects with low bits 000, and null was a null pointer (0), so it looked like an object. Compatibility keeps the quirk alive.

4. null vs undefined

null usually means intentionally empty; undefined means unassigned or missing. Prefer null for explicit API “empty” and undefined for omission.

5. Correct Type Checks

if (value !== null && typeof value === "object") { /* real object (incl. arrays) */ }
Array.isArray([]);
Number.isNaN(NaN);
Number.isFinite(42);

function isObject(value) {
  return value !== null && typeof value === "object" && !Array.isArray(value);
}

6. Boxing Caveat

const s = new String("hi");
typeof s;   // "object"
s === "hi"; // false

Avoid primitive wrapper constructors in application code.

Chapter Summary

  • Values are primitives (7) or objects; functions typeof as "function".
  • typeof null === "object" is a historical artifact kept for compatibility.
  • null is intentional emptiness; undefined is missing/unassigned.
  • Guard null; use Array.isArray and Number.isNaN/isFinite.
  • Skip primitive wrappers; remember Symbol/BigInt typeof results.
