Part 9: The Event Loop and Macro/Microtask Queues

JavaScript user code is largely single-threaded. Timers, network I/O, and events coexist because the Event Loop coordinates the Call Stack with task queues.

1. One Turn (Simplified)

  1. Run synchronous code
  2. Drain all microtasks
  3. Possible render (browsers)
  4. Run the next macrotask
  5. Repeat

2. Macrotask vs Microtask

Macrotasks: setTimeout, I/O callbacks, UI events.
Microtasks: Promise.then, queueMicrotask, MutationObserver.

console.log("script start");
setTimeout(() => console.log("timeout"), 0);
Promise.resolve().then(() => console.log("promise"));
console.log("script end");
// start → end → promise → timeout

3. Why setTimeout(0) Still Waits

It queues a task after the current stack and microtasks—not “run in 0ms.”

4. async/await

async function run() {
  console.log("A");
  await null;
  console.log("B");
}
console.log("C"); run(); console.log("D");
// C A D B

5. Starvation Warning

// Unbounded microtask chains can starve rendering/timers
function spam() { Promise.resolve().then(spam); }

Chapter Summary

  • The event loop runs queued work when the call stack is empty.
  • Microtasks outrank macrotasks.
  • setTimeout(0) still waits until after sync + microtasks.
  • Code after await resumes as a microtask.
  • Unbounded microtask chains can starve the UI.
