01. What is React Native? (Differences from React)

Hello there! Today, we are taking our first steps into the world of mobile app development by exploring React Native (RN). If you have experience in web development or have worked with React, RN is an incredibly appealing framework. But why should we use it? And how exactly does it differ from React in a web environment?

1. Differences in Rendering: Web Development (React) vs. Mobile Apps (RN)

React operates in the browser, utilizing HTML, CSS, and JavaScript to manipulate the DOM (Document Object Model) and render the screen. When we use tags like <div> or <span>, the browser interprets them and draws them onto the screen.

However, mobile operating systems (iOS and Android) are not browsers. iOS draws screens using UIView written in Objective-C or Swift, while Android uses View written in Java or Kotlin.

This is where React Native works its magic. It maps the JavaScript code we write into native components (UIView, View) that the native operating system can understand and render natively.

2. The Core Architecture of React Native: The Bridge

How does JavaScript code get converted into native elements? It's all thanks to the core architecture of RN: The Bridge.

The Bridge acts as a communication channel between the environment where JavaScript code runs (JS Thread) and the environment where native code runs (Native Thread), allowing them to exchange messages asynchronously.

💡 Core Metaphor: "The Interpreter (Bridge)"
Think of it like this: If you give instructions in Korean (JavaScript), the interpreter (Bridge) translates them into English (iOS) and Spanish (Android), giving commands to the local workers (Native Thread).

When we send a message via JavaScript saying "Draw a button here" through the Bridge, iOS creates a UIButton and Android creates an android.widget.Button to display on the screen.

3. Practice: Setting Up the RN Environment (Expo vs. CLI) & Running 'Hello World'

There are two primary ways to start a React Native app: Expo CLI and React Native CLI.

  • Expo CLI: A toolchain that helps you start developing apps quickly without complex native setups. Highly recommended for beginners.
  • React Native CLI: Used when you need to touch native code (Java, Objective-C, etc.) directly or when custom native modules are required.

Hello World Tutorial using Expo

1. Create an Expo Project
Open your terminal and enter the following commands:

npx create-expo-app HelloWorld
cd HelloWorld

2. Run the App

npx expo start

3. Edit the Code
Open the App.js file in your project folder and modify it as follows:

import { StatusBar } from 'expo-status-bar';
import { StyleSheet, Text, View } from 'react-native';

export default function App() {
  return (
    <View style={styles.container}>
      <Text>Hello World! This is my first React Native app.</Text>
      <StatusBar style="auto" />
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#fff',
    alignItems: 'center',
    justifyContent: 'center',
  },
});

After saving, check the Expo Go app (or simulator) and you will see 'Hello World!' displayed on your screen.

Chapter Summary

  • React vs React Native: React manipulates the DOM to render in a browser, whereas React Native maps to native components (iOS, Android) to render on mobile devices.
  • Bridge Architecture: Acts as an interpreter between the JavaScript environment and the Native environment, sending and receiving messages asynchronously.
  • Expo vs CLI: Choose Expo for a quick start and convenience, or React Native CLI if you need fine-grained control over the native layer.
