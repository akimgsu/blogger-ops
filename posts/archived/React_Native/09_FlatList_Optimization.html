09. Rendering Large Datasets (FlatList & Performance Optimization)

When building apps, you frequently need to display lists containing dozens or hundreds of items (e.g., a WhatsApp contact list, an Instagram feed). To make a screen simply scrollable, you could use a <ScrollView>. However, if your data exceeds a few hundred items, your app might lag or even crash. Today, we'll learn about <FlatList>, the essential component for performance optimization when rendering lists.

1. The Limits of ScrollView and the Introduction of FlatList

If you have 1,000 items, a <ScrollView> will render (load into memory) all 1,000 of them at once, even the 990 items that are currently off-screen. Naturally, this wastes device memory and severely slows down the app.

In contrast, <FlatList> employs a technique called Lazy Loading. It wipes off-screen items from memory and renders them in real-time just as the user scrolls them into view.

💡 Core Metaphor: "Sushi Conveyor Belt"
- ScrollView: The chef makes all 1,000 sushi rolls at once and piles them onto your table. (The table breaks = the app crashes).
- FlatList: The chef only places sushi on the 10 plates passing right in front of the customer. Plates that have passed are cleared, and new sushi is placed only on approaching plates via a conveyor belt system.

2. The 3 Core Props of FlatList

To use FlatList effectively, you must understand three mandatory (or highly recommended) Props.

  1. data: The source array of data you want to render. (e.g., [{id: 1, name: 'A'}, {id: 2, name: 'B'}])
  2. renderItem: A function that defines how each item in the data array should be drawn as UI.
  3. keyExtractor: A function that extracts a unique Key for each item. React uses this to track items and optimize rendering.

3. Practice: Implementing an Infinite Scroll List

Let's build a FlatList capable of smoothly scrolling through hundreds of mock data entries.

import React, { useState } from 'react';
import { View, Text, FlatList, StyleSheet, SafeAreaView } from 'react-native';

// 1. Generate 100 mock data entries
const INITIAL_DATA = Array.from({ length: 100 }, (_, index) => ({
  id: String(index + 1),
  name: `User ${index + 1}`,
}));

export default function UserListApp() {
  const [users, setUsers] = useState(INITIAL_DATA);

  // 2. renderItem function: Defines how to draw each item
  // We destructure { item } from the parameter
  const renderUserItem = ({ item }) => (
    <View style={styles.itemContainer}>
      <Text style={styles.itemName}>{item.name}</Text>
    </View>
  );

  return (
    <SafeAreaView style={styles.container}>
      <Text style={styles.headerTitle}>Contact List (FlatList)</Text>
      
      {/* 3. Applying the FlatList component */}
      <FlatList
        data={users}                           // Source data array
        renderItem={renderUserItem}            // UI rendering function
        keyExtractor={(item) => item.id}       // Unique Key extraction function
        
        // Options for performance and infinite scrolling (for reference)
        initialNumToRender={10}                // How many items to render initially
        onEndReached={() => console.log('Hit the bottom! Need to load more data')}
        onEndReachedThreshold={0.5}            // Trigger event when 50% away from the bottom
      />
    </SafeAreaView>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#f8f9fa',
  },
  headerTitle: {
    fontSize: 24,
    fontWeight: 'bold',
    textAlign: 'center',
    padding: 20,
    backgroundColor: '#fff',
  },
  itemContainer: {
    padding: 20,
    borderBottomWidth: 1,
    borderBottomColor: '#eee',
    backgroundColor: '#fff',
  },
  itemName: {
    fontSize: 18,
  }
});

Run this code and scroll as fast as you can. Even with 100 (or 10,000) items, the app won't stutter; it scrolls buttery smooth. This is because FlatList intelligently renders only the items visible on the screen. By utilizing the onEndReached property, you can easily implement an Infinite Scroll feature that requests the next page of data from the server the moment the user hits the bottom.

Chapter Summary

  • ScrollView vs FlatList: ScrollView loads all data into memory at once causing performance degradation, whereas FlatList renders only visible data (lazy loading) to optimize memory.
  • Sushi Conveyor Belt Metaphor: FlatList acts like a conveyor belt, placing data only on the plates currently in your viewport.
  • Essential Props: They work as a trio: data for the source array, renderItem to draw the UI, and keyExtractor to pull out unique identifiers.
