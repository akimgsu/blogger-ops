# 핵심 요약: 09. 대량의 데이터 렌더링 (FlatList와 성능 최적화)

- **왜 ScrollView 대신 FlatList인가?**
  - `<ScrollView>`: 데이터 개수와 상관없이 화면에 안 보이는 요소까지 모두 렌더링 (메모리 낭비, 앱 크래시 위험).
  - `<FlatList>`: 현재 화면(Viewport)에 노출된 항목들만 실시간으로 렌더링(Lazy Loading).
  - 💡 **핵심 비유**: 수천 개의 초밥을 미리 다 만들어 쌓아두지 않고, 손님 눈앞을 지나가는 빈 접시에만 초밥을 올려주는 **"회전초밥집 컨베이어 벨트"**.

- **FlatList 3대 필수 Props**
  1. `data={배열}` : 리스트로 뿌려줄 원본 데이터.
  2. `renderItem={함수}` : 배열의 각 항목(`item`)을 어떤 UI 구조로 그릴지 정의.
  3. `keyExtractor={함수}` : 각 항목의 고유 ID를 지정하여 React의 렌더링 추적 최적화.

- **실무 활용 팁 (무한 스크롤)**
  - `onEndReached`: 스크롤이 바닥에 닿았을 때 실행될 함수 (다음 페이지 API 호출용).
  - `onEndReachedThreshold`: 바닥에 닿기 얼마 전(비율)에 함수를 미리 실행할지 결정.
